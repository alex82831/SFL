# 性能优化记录

**针对 SFL 0.8.2 之后的改造** · 解释执行与编译执行两侧

本文记录一轮以性能为目标的全面改造：动了什么、为什么是这些、快了多少、怎么验证。
出发点是[《评估-内置函数改用标准库实现》](评估-内置函数改用标准库实现.md)的结论：
让程序变快的杠杆不在"把内置函数换个语言实现"，而在**让编译器看穿更多调用**、
**让装箱代码少装箱**。本轮把那份评估 §五 列出的方向全部落了地。

所有数字都是在同一台 Linux x86_64 机器上、对改造前后的两个构建实测的中位数
（每项三轮）；绝对值随机器变化，倍数可复现。行为回归由全部测试套件钉住：
差分测试 22 个套件解释与编译输出逐字节一致，`tests/run.sh` 全绿，
编译器用例 37 个全过（含新增的 `tests/compile/accept/unboxed_paths.sfl`）。

---

## 一、编译侧

### 1. 内联表从 16 个扩到 47 个（`Intrinsics.scala`）

参数类型已知时直接生成机器指令的内置函数，新增 31 个：

- 带定义域检查的 `sqrt` `log` `log2` `log10` 走 `sfl_*_ck` 助手——同一个检查、
  同一条消息，少了两次装箱一次拆箱；
- `cbrt` `tan` `asin` `acos` `atan` `sinh` `cosh` `tanh` `atan2` `hypot` 直接调用
  原语自己调用的 libm 符号，结果逐位相同；
- 位运算 7 个照 JVM 语义开码（移位量取模 64）；`doubleToBits`（NaN 归一）、
  `bitsToDouble` 是一两条指令；
- `clamp` `lcm` `parseInt` `parseFloat` `isNaN` `isInfinite` `random` `timeNanos`。

实测：浮点循环里的 `acc += sqrt(x)` 从 375 ms 到 **23 ms（16 倍）**——评估报告里
用 `pow(x, 0.5)` 与 `sqrt` 对照测出的那道 27 倍鸿沟，就此填平（现在两种写法都是
14–23 ms）。

### 2. 原语结果表：参数未知，结果仍然有类型（`Intrinsics.PrimRet`）

约 80 个原语的结果被逐一对照 C 实现验证为"必然是某一种机器类型，否则抛错不返回"，
编译器据此把结果以裸机器值读出，推断在调用之后不塌成 `Dyn`：

- `length`/`size`/`indexOf`/`lastIndexOf`/`strFind`/`ord` 另有免装箱的孪生入口
  （`sfl_length_i` 一族），连结果单元都不分配；
- 全部 `is*` 判定、`contains`/`startsWith`/`endsWith`/`has`/`isEmpty` 的布尔结果
  是单例，读出是一次指针比较；
- 十个类型判定（`isInt`/`isString`/…）更进一步：动态参数直接开码成一次 tag 载入
  加比较（布局由 `sfl.h` 的静态断言钉住），机器类型参数在编译期就是常量。

这是 `while (i < length(arr))` 的 `i` 保持 i64 的原因——从此整个循环骨架都不装箱。

### 3. 通用入口的局部变量拆箱（`Compile.scala`）

原先通用入口（一切被动态调用的函数——标准库全部在内）把**每个**槽都定成 `Dyn`，
连 `var i = 0` 都装箱。现在函数体不创建闭包时，证明出机器类型的局部变量住进自己
的带类型 alloca，装箱槽数组只留参数与动态局部。体内有闭包的函数不变（每个槽都
可能被捕获）。

### 4. 机器整数下标与混合算术（`sfl_value.c`）

- `a[i]`、`a[i] = v`、`a[i] += v` 的键是 i64 时走 `sfl_index_get_i` 一族：不装箱键、
  不做动态下标检查；错误路径装箱后交回通用例程，消息逐字节相同；
- 算术一侧是机器数、另一侧是动态值时走 `sfl_arith_iv` 一族：机器侧不装箱，
  另一侧照常按 tag 分派。

### 5. 运行时驻留单元（`sfl_value.c`）

128 个 ASCII 单字符字符串与空字符串成为不进堆、不被回收的静态单元（哈希预先算好），
与既有的 -128..1024 小整数缓存、`null`/`true`/`false` 同一机制；`s[i]`、`charAt`、
字符串迭代与一切逐字符循环从此不分配。回收器无需改动——页测试本来就会跳过堆外指针。

### 编译侧实测（中位数）

| 基准（编译后） | 前 | 后 | 加速 |
| --- | --- | --- | --- |
| `acc += sqrt(x)` 浮点循环 | 375 ms | 23 ms | **16.3x** |
| indexOf 的纯 SFL 重写 | 173 ms | 40 ms | **4.3x** |
| `sum`（标准库 SFL 实现） | 180 ms | 95–100 ms | **1.8x** |
| base64Encode（标准库 SFL 实现） | 310 ms | 162 ms | **1.9x** |
| hexEncode（同上） | 368 ms | 222 ms | 1.7x |
| reverse 的纯 SFL 重写 | 357 ms | 245 ms | 1.5x |
| 正则引擎（bench/stdlib.sfl 三项） | 85 / 16 / 26 ms | 68 / 12 / 20 ms | ~1.25x |
| assocIn/getIn | 19 ms | 14 ms | 1.4x |
| sort / sortBy | 4 / 5 ms | 3 / 4 ms | ~1.25x |

评估报告里的反常在收敛：base64 的 SFL 实现编译后曾**慢于**解释执行（310 对 245），
现在 162 对 230，重新快于解释；hex 从 368 对 222 变为 222 对 231，两侧打平；
reverse 从 357 缩到 245，仍慢于解释的 131——它的成本已经全在逐字符 `push` 与
`join` 的拷贝里，是"没有字符串构建器就写不快"的那一类，评估报告早已点名。
`sum` 编译后曾是解释器原生实现的 15 倍慢，现在收窄到 9 倍。已经是机器类型的代码
（fib、loop、nbody 编译后 1.4–2.1 ms）不受影响——这轮改造动的全是原先装箱的那一侧。

## 二、解释侧（`Ast.scala`、`Value.scala`、`BuiltinsText.scala`）

解释器此前已有小整数缓存、Int/Int 快路径、尾调用蹦床，余量本就不大；本轮补三处：

1. **单字符 `VStr` 驻留**（ASCII 128 个）：`s[i]`、`charAt`、`chr`、字符串迭代
   共用，逐字符循环少一次分配；
2. **字符串拼接快路径**：`VStr + VStr` 直接拼接，跳过 `display` 的
   StringBuilder 往返；数字侧用 `Long.toString`/`formatDouble` 直出；
3. **字面量 select 的哈希分派**：case 全为字符串（或全为整数）字面量且不少于
   4 个时，构造期建一张哈希表，求值期一次查找取代逐个比较链。语义不变：非字符串
   主体不可能等于任何字符串 case，径直走 default，与比较链的判断一致；整数表上的
   浮点主体按 `Values.equal` 的桥接规则（整值往返校验）查表。重复 case 首个生效。

实测：regex 三项、`replace` 胶水、`map+filter+reduce`、`assocIn/getIn` 各快
1.2–1.3 倍，逐字符循环快约 1.1 倍；纯数值基准（fib/loop/nbody）在噪声带内不变。

## 三、一致性

- `./tests/differential.sh`：22 个套件解释与编译输出逐字节一致，0 差异；
- `./tests/run.sh` 全部通过（语言、内置、模式、并发、IPC、包、示例、LSP/DAP、
  构建工具、命令行）；
- `tests/compile/`：37 个用例全过。新增 `accept/unboxed_paths.sfl` 专门钉住本轮
  全部快路径：通用入口机器局部、结果表原语喂类型化代码、数值/位/判定内联、
  机器整数下标（含负下标与越界消息）、混合算术（含错误路径）、驻留字符行为；
- 编译器手册相应更新：§5 内联表与两个新小节、§6 驻留单元、§13 新增原语的
  第 5 步（登记 `PrimRet` 的要求）。

## 附：复现

```bash
sbt nativeLink
./tests/run.sh && ./tests/differential.sh          # 先绿再谈快
./bench/compile.sh                                  # 解释 vs 编译
sfl bench/stdlib.sfl                                # 标准库热路径，解释
sfl -c bench/stdlib.sfl -o /tmp/bs && /tmp/bs       # 同上，编译
sfl bench/dispatch.sfl                              # 分派三式
```

评估报告附录的三个微基准（codec 天然对照、字符串原语改写、层开销与 sqrt/pow 对照）
同样适用于前后对比。
