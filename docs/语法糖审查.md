# SFL 语法糖审查

**现状盘点、候选评估与本轮实现** · SFL 0.6.0

评判标准取语言的设计目标:**简单**(一件事一种写法,规则短到一句话)、**自由**
(不强加范式,可与既有语法自由组合)、**易用**(高频痛点优先)、**易记忆**
(借用使用者已有的肌肉记忆,而不是发明新记号)。

每个决定还要过两道 SFL 特有的闸门:**双引擎逐字节一致**(最好在解析期脱糖,
让解释器与编译器根本无从分歧)与**零破坏**(现有代码含义不变,逐一实测)。

---

## 一、现状盘点

解析器里已有的糖,按引入时期:

| 糖 | 展开 | 备注 |
| --- | --- | --- |
| `o.name` | `o["name"]` | 手册承诺二者等价 |
| `a[-1]` | 末尾倒数 | |
| `a[i] += v` 等五种复合赋值 | 读-改-写,收方与键只求值一次 | 专用节点 |
| `x \|> f(y)` | `f(x, y)` | 解析期降解,静态调用 |
| `if/elsif/else then` | 表达式化条件 | 块值即尾语句值 |
| `def f(a)(b)` | 柯里化定义,嵌套闭包 | |
| `...rest` 形参 / `p = 默认值` | | |
| `"""..."""` | 跨行字符串 | |
| `'...'` | 与 `"` 等价的字符串(本轮起:不再插值) | |
| 模式匹配全家(0.6.0) | 解析期脱糖为普通节点 | `{name}` 简写、`$x` 钉住等 |
| `a[i, j]`(0.6.0) | `a[i][j]` | |
| `(a, b)` 元组字面量(0.6.0) | | |

盘点结论:SFL 的糖有一个统一的实现传统——**解析期脱糖**,两个引擎看到同一棵
树。本轮延续这个传统,六个新糖全部零编译器改动、零运行时改动。

## 二、本轮采纳(六项,全部已实现)

### 1. 字符串插值 `"${expr}"`

最高频的痛点:语料里 `"a " + x + " b"` 式拼接俯拾皆是。规则一句话:**只有
`${表达式}` 有魔法**;`$` 单独出现是字面量(`"$5.00"` 安全),`\$` 显式转义。
刻意不做 `$name` 简写——它才是与真实文本冲突的根源。

展开为 `("a" + x) + "b"`:字符串 `+` 本就用 display 渲染右侧,插值与拼接因此
**不可能**有两种行为。支持任意嵌套(`${}` 里可以再有插值串)。三引号跨行串
同样插值。

```sfl
println("你好,${name}!共 ${size(xs)} 项")
```

### 2. 单引号不插值(shell 二分法)

`'...'` 保留转义但**不插值**。双引号有魔法、单引号没有——这是几亿人已有的
shell 肌肉记忆,也让"想写一大段含 `$` 的文本"有了不需要转义的出口。
(语料实测:单引号字符串零使用,此调整无破坏。)

### 3. 原始字符串 `r"..."` / `r'...'`

Python 的 r 前缀:**没有任何处理**——无转义、无插值。正则的反斜杠不再翻倍:
`matches(s, r"[a-z]\d+")`。`r"""..."""` 顺带得到跨行原始串。

### 4. 空安全跳 `?.`

动态语言里逐层下钻 JSON 是日常,而 SFL 的缺键是**报错**(这是对的,错字该炸)。
`?.` 提供显式的宽恕通道,规则是**局部的**一句话:

> `o?.k` 这一跳:接收者为 null → null;对象缺键 → null;其余与 `.k` 完全相同
> (包括它的报错)。

与 JS 的差异(有意为之):`?.` 不会让**后续**未标记的跳变宽容——`o?.k.j` 在
`o` 为 null 时照样报错,想宽恕哪一跳就在哪一跳写 `?.`。没有隐蔽的短路传播,
规则不出这一跳。紧随的调用属于本跳:`api?.ping()` 在键缺失或值为 null 时得
null 而不炸。

展开用隐藏槽保证接收者只求值一次;缺键路径经 `get(o, k, null)`,非对象接收者
走严格 `Index` 保留原有的高质量报错。

### 5. 空合并 `??`

`a ?? b`:a 为 null 才取 b,b 惰性求值。与 `?.` 是天然搭档:

```sfl
val host = conf?.server?.host ?? "localhost"
```

与 `||` 同优先级、左结合。注意 SFL 的 `||` 返回**布尔**而非操作数(与 JS 不同),
所以"用 `||` 凑默认值"的 JS 习惯在 SFL 本来就不成立——`??` 是唯一正确的拼法,
这反而更简单。

### 6. 裸参 lambda 与 shebang

单参数 lambda 免括号:`map(xs, x -> x * 2)`;花括号形式同理 `{ x -> ... }`。
多参数、零参数、默认值、rest 仍需括号——规则:**一个名字直接跟箭头,才是糖**。

脚本首行 `#!/usr/bin/env sfl` 被跳过,配合 `chmod +x` 直接执行——工具脚本
语言的本分。

## 三、评估后否决(九项,附理由)

| 候选 | 否决理由 |
| --- | --- |
| 区间字面量 `1..10` | `range()` 已短且唯一;`..`/`...` 相邻易混(rest 参数);闭开语义各语言不一,记忆负担大于收益 |
| 三目 `?:` | `if then else` 已是表达式,第二种写法违背"简单" |
| `++` / `--` | `+= 1` 已存在;语句/表达式语义争议大,Python/Rust 同样否决 |
| 对象字面量简写 `{name}` | 与块 `{x}` 语法歧义(`{a, b}` 可行但"为何 `{a}` 不行"更难记);模式侧无歧义故保留 |
| 尾随 lambda(Kotlin 式) | `{ (x) -> }` 作实参已可用;行首 `{` 与块的歧义换一个逗号不值 |
| 链式比较 `a < b < c` | 改变现有表达式含义;C 系用户会误读;脚本场景低频 |
| `in` 表达式(`k in o`) | `has`/`contains` 已存在;与 `for..in` 头部的模式扫描互相绞缠 |
| 占位符 lambda(Scala `_`) | 作用域规则出了名的难记,Scala 自己也在收缩 |
| `else if` 别名 | `elsif` 已定;两种拼法违背"一件事一种写法" |

另有两项**留待观察**:元组赋值交换 `(a, b) = (b, a)`(解构 val 已覆盖多数
场景,对既有变量的模式赋值等出现真实需求再做);插值内语法高亮(纯装饰)。

本轮审查顺带确认了一处**既有**歧义(先于本轮存在,与新糖无关):无括号 lambda
体位置的 `{` 被读作 lambda 体,所以 `() -> {"a": 1}.a` 里的 `.a` 落在 lambda
自身上而非对象上。规避写法是加括号:`() -> ({"a": 1}).a`。要根治得让 lambda 体
的花括号消歧看穿"对象字面量后跟后缀"的形状,收益与风险都不大,记录待议。

## 四、验证

- `tests/sugar.sfl`:72 断言(57 + 对抗审查补充 15),解释执行全过,**编译产物逐字节一致**;
- 对抗回归(本轮加固):插值四层嵌套、百段插值、守卫内插值、`?.` 全类型接收者与
  错误传播、嵌套函数默认参数里的 `??`/`?.`(隐藏临时改走全局槽,修复编译器内部
  崩溃)、`?.` 调用命中非函数时不再泄漏隐藏临时名(两引擎措辞一致)、单行字符串
  断行改为带位置的硬错误(REPL 不再陷入永不能完成的续行)、三引号串纳入转义表
  (`\$` 可写出字面量 `${`);
- 兼容性:全语料实测——`${` 仅出现于注释、`$` 的既有用法全部落在"单独 `$`
  不插值"的安全侧、单引号字符串零使用、`r"`/`?.`/`??`/裸参箭头此前均为语法
  错误(自由语法位);
- REPL:未闭合的 `${` 触发续行提示;`?.`/`??` 结尾同样续行;
- 全量回归:既有 14 个套件 + 差分测试无一变化。
